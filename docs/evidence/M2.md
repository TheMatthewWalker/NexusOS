# M2 — Hardened Core v0.2 acceptance evidence

Each roadmap gate below names the automated check that proves it, where that
check runs, and anything that still needs a person. "Mutation-verified"
means the check was deliberately broken in the code and the test was seen to
fail, so it cannot pass vacuously.

| Gate | Evidence | Runs in |
|---|---|---|
| IPC authenticates the invoking local user | Unix socket is the Linux default. Kernel `SO_PEERCRED` UID must equal Core's UID, and a bearer token is required on every endpoint. `scripts/ci/cross-user.sh` gives user B the token and loosened permissions, and B is still rejected before HTTP (mutation-verified). `CoreApiTests.EveryEndpointRequiresTheBearerToken` | Core CI |
| Per-user storage | Two real Linux accounts run their own Core. Neither can list or read the other's 0700 state directory, 0600 token or 0600 SQLite, and histories never cross. Restart preserves this (`cross-user.sh`) | Core CI |
| Credentials in OS keyring, not config | Real gnome-keyring over a private D-Bus session: an unlocked secret is used in the `Authorization` header, missing, locked or unavailable keyrings fail closed, and there is no plaintext environment fallback. Each phase asserts the exact count of executed tests ([keyring detail](M2-keyring.md)) | M2 Real Secret Service |
| SQLite state with retention | Atomic legacy import with rollback and a single retry, no re-import, malformed and null-field rows skipped, count/age/future-date retention, clear-history leaving no prompt bytes on disk (`secure_delete`, mutation-verified), permission re-tightening, symlinked state files rejected (`SqlitePersistenceSecurityTests` and earlier suites) | Core CI |
| Rate limiting and cancellation | 20 chats/min, then 429. One inference slot: a second concurrent request gets 429 and the slot is released afterwards. Client cancellation reaches the provider and nothing is saved (`CoreApiTests`) | Core CI |
| Explicit cloud egress policy | Without `NEXUS_CLOUD_EGRESS_ALLOWED=true`, the keyring is never read and nothing is sent. Failover between providers does not exist, so it cannot happen implicitly | Core CI |
| Request size, allowlisting, SSRF | 64 KiB body limit gives 413 (smoke test). The prompt length bound is enforced before any provider call. The HTTPS:443 allowlist rejects literal IPs. DNS is resolved once per connection and every answer is validated: mixed answers fail closed, rebinding to a private address is rejected, and each validated address is tried in turn (IPv6 fallback). Redirects are returned, never followed, and proxies are disabled (`CloudConnectorTests`, `CloudAddressPolicyTests`) | Core CI |
| No secrets in logs | Logs captured at Trace across a successful and a failing cloud call contain no Core token, API key, prompt or answer. This test found, and now guards, a real leak: HttpClient's Trace logging printed the cloud `Authorization` header. All outbound header values are now redacted | Core CI |
| Meaningful errors | Missing Ollama model gives an `ollama pull` hint. An unreachable engine, timeout, malformed, empty or oversized response, upstream 401/429/5xx and bad configuration all give safe messages that never echo upstream bodies (`ModelProviderTests`, `scripts/acceptance/m1-live.sh`) | Core CI, M1 Live Model |

## Known limitations (accepted for M2)

- TCP mode (`NEXUS_API_MODE=tcp`) is an explicit development opt-in. It is
  loopback plus a bearer token, with no kernel peer identity. Any local user
  can attempt connections there, but cannot read the token.
- Root can read every user's state. Encryption at rest is not provided.
  Treat history as plaintext.
- State-path symlink checks are path-based, not race-free `openat2`.

## Removing legacy plaintext backups after migration

The first SQLite start imports `provider.json` and `history.jsonl` and
deliberately keeps them as backups. Once you have confirmed the migration:

```bash
nexus history                                    # 1. confirm imported conversations are present
cd "${NEXUS_STATE_DIR:-${XDG_STATE_HOME:-$HOME/.local/state}/nexusos}"
shred -u history.jsonl provider.json 2>/dev/null || rm -f history.jsonl provider.json   # 2. remove
```

`shred` is best effort. On SSDs, copy-on-write filesystems (btrfs, ZFS) and
anything that is snapshotted or backed up, old blocks can survive. Only
full-disk encryption protects against that.
