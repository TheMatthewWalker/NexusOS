# M3 — Guardian preview and approval evidence

Design: [ADR-002](../adr/002-guardian-candidate-model.md).

| Gate | Evidence | Runs in |
|---|---|---|
| One allowlist, one ID scheme | `schema/guardian-options.json` is embedded by C# and read by Python. Both reproduce `schema/guardian-vectors.json` byte for byte (`GuardianSchemaVectorTests`, `test_schema.py`), and a test fails if any implementation carries its own copy of the option names | Core CI, Guardian Validation, Nix package check |
| Typed plans only | Unsupported, duplicate, wrongly typed and injected options are rejected on both sides of the boundary, and Core never forwards an invalid plan (`GuardianBrokerIntegrationTests`) | Core CI |
| AI proposes, never decides | `/guardian/propose` accepts only an exact typed object or refusal. Self-approval fields, Nix injection, look-alike options, duplicate keys, prose, multiple objects, deep nesting and oversized output are rejected (23 hostile cases). Users cannot close the request fence. A proposal is a preview and is never submitted (`GuardianProposerTests`). A real model gives a preview or a clean 422 (`m1-live.sh`) | Core CI, M1 Live Model |
| Builder attestations | Ed25519 over a canonical statement naming the toplevel and derivation. Changing any field breaks the signature. Unknown keys, stale or future statements and malformed shapes are rejected. The broker holds public keys only, and the key file must not be writable by others (`test_attestation.py`) | Guardian Validation |
| Root approval | An interactive root console must type `APPROVE <candidateId>`. Approval binds one candidate to one UID, expires after 120 s, and is consumed by its review whatever the outcome (`test_trusted_issuer.py`, broker VM test via a real pseudo-terminal) | Guardian Validation, Guardian NixOS VM |
| Independent decision | The broker re-observes the running generation and denies stale baselines, failed checks, forged attestations, outputs missing from the store and deriver mismatches. Decisions form a hash-chained ledger with tamper detection, and a permitted decision can be staged only once (`test_root_review_broker.py`) | Guardian Validation |
| Privileged service | NixOS module: root with no capabilities, no network (`PrivateNetwork`, `IPAddressDeny`), `ProtectSystem=strict`, task and memory limits. State 0700, ledger 0600, socket `root:nexus-guardian 0660`. Users outside the group cannot connect; group members outside `allowedUsers` are dropped by `SO_PEERCRED`. Decisions persist across restarts (`nix/tests/guardian-broker.nix`) | Guardian NixOS VM |
| Full stack | Per-user Core systemd services submit through the real broker socket, and a non-allowlisted user's Core gets 403. A SIGKILLed Core is restarted despite its stale socket (`nix/tests/nexus-stack.nix`) | Guardian NixOS VM |
| Wire protocol | Length-framed JSON with timeouts. Split frames are reassembled, and oversized and malformed frames are refused. Idle clients don't block others; concurrency is bounded. A stale socket is replaced but a regular file never is (`BrokerProtocolTests`) | Guardian Validation |

## Findings fixed during this work

- **Subclass dispatch:** broker dispatch bypassed subclass overrides. Found by the cross-language end-to-end test.
- **Unreliable allowlisted option:** `services.flatpak.enable = true` does not evaluate on NixOS 26.05 without XDG portals. Signed evaluate/build checks exist precisely so a change like this can never be attested.
