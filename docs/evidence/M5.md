# M5 — Inference manager evidence

| Gate | Evidence | Runs in |
|---|---|---|
| llama.cpp adapter | OpenAI-compatible routing, plus an optional **Core-managed** `llama-server`. It starts on demand with loopback-only arguments and Core's context budget, is health-gated, reports a crash during startup, and is stopped on `nexus unload` and Core shutdown (`LlamaServerProcessTests`; real llama.cpp in `m1-live.sh`) | Core CI, M1 Live Model |
| Context/KV budget | `NEXUS_CONTEXT_TOKENS` and `NEXUS_MAX_OUTPUT_TOKENS` are validated at startup and sent as `num_ctx`/`num_predict` (Ollama), `--ctx-size` (managed llama.cpp) and `max_tokens` | Core CI |
| RAM/VRAM monitoring | `/inference/telemetry`: `/proc/meminfo` and the first NVIDIA GPU via `nvidia-smi`; missing data reported as null | Core CI |
| Eviction and idle sleep | Explicit unload for the selected provider, and optional idle unload (`NEXUS_MODEL_IDLE_SECONDS`) for any provider that supports it | Core CI |
| Measured reclaim | `scripts/bench/nexus_inference_bench.py` reports cold start, warm latency and RAM/VRAM idle, loaded and after unload, through Core. It reports reclaim and never infers it (`tests/bench`) | Core CI, M1 Live Model (CPU, real model) |
| Application priority | Concurrency gate (1 inference slot by default; extra requests get 429). Foreground-app preemption is **not implemented**: it needs desktop integration (M6) | — |

## Reference-hardware runs (operator gate)

Run each profile on the machine it describes, then paste the JSON below:

```bash
nexus-core &   # or the per-user service
python3 scripts/bench/nexus_inference_bench.py --provider local --provider llama-cpp \
  --profile gpu-8gb --runs 5 --output m5-gpu-8gb.json
```
