## Results

The `hyprland-desktop` VM test passes on GitHub's runners (KVM, about 6 minutes for the whole Desktop workflow). It also passes locally under software emulation (TCG, no KVM), where each stage is much slower:

| Stage | What it proves | Local TCG time |
|---|---|---|
| Login | greetd logs alice into Hyprland. Hyprland starts the shell, and Core answers from the mock model. All four layer surfaces are present and the shell reports `online` | ~110–135 s |
| Launcher | A real click on the launcher opens the full Nova core | ~26–31 s |
| Question | Text typed through the kernel input device reaches Core. The streamed answer is in Core's history | ~32–46 s |
| App from orbit | Terminal opens from the orbit (a real `kitty` client in Hyprland) and the shell steps back | ~80–180 s |
| Offline | With Core stopped, the shell says "Offline · apps still work". Terminal still opens from the orbit. When Core starts again, the shell goes back online | ~170 s |
| Lock | hyprlock covers the launcher (pixels under it go dark) | ~100 s |

Software rendering can drop a click that lands mid-frame, and can leave Hyprland too busy to answer its IPC. So the test confirms each step through the shell's IPC state and retries; it never assumes a click landed.

The screenshots are uploaded by the Desktop workflow as the `nexus-desktop-screenshots` artifact (on a passing run): `01-desktop`, `02-core`, `03-answer`, `04-app-open`, `05-offline`, `06-before-lock`, `07-locked`.
