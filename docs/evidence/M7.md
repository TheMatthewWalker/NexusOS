## Found by installing for real

- The login screen's greeter account is a system user with no writable home, but it still got a Core, which crashed in a loop. Core now runs only for people's accounts (`ConditionUser=!@system`), and the installer test fails if Core crashes after boot.
- The installer terminal had no monospace font, so its text was spaced out. Fixed by installing JetBrains Mono as the desktop's monospace font.
- Locking the flake inside `nixos-install` changed the flake mid-build. It is now locked first.
- On a real laptop, Wi-Fi could not be joined from the live USB. The panel's Wi-Fi control was only an on/off switch, and the image had turned off wpa_supplicant (`networking.wireless.enable = mkForce false`), which NetworkManager needs, so no tool could join a network. The image now keeps it, CI checks that, and the panel lists networks and takes passwords.
- Building the Wi-Fi test found three more: the panel took the first Wi-Fi adapter even if NetworkManager did not manage it; rebuilding every row on each scan could put a click on the wrong network (rows now persist, through `ScriptModel`); and a saved open network was labelled Secured.
- Offline, emptying Nix's substituters also dropped the one `nixos-install` uses to copy from the USB stick, so it tried to download nixpkgs. Offline now only shortens the connection timeout.

## Still open

- A themed login screen. The installed system uses tuigreet, a plain text login.
- Disk encryption, dual boot, a graphical installer and Guardian on installed systems ([INSTALL](../INSTALL.md#not-in-this-alpha)).
- Wi-Fi that needs a username or certificate (work and school networks) is set up with `nmtui`, not the panel.
- The model on the image needs `nix run .#lock-model` once, on a machine that can reach the Ollama registry.
- Installing on real hardware (operator gate).
